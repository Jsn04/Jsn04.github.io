Subject-Disjoint Cross-Dataset Evaluation of CNN and CNN-LSTM Models for Visual Driver Drowsiness Detection

Most drowsiness detection benchmarks evaluate on the same subjects the model trained on. This paper builds a three-protocol evaluation framework that tightens generalization conditions step by step, culminating in a subject-disjoint cross-dataset setup where the model is tested on six drivers it has never seen, on a benchmark it was never trained on. The result: a 59.77 percentage point domain-shift gap that standard protocols simply cannot see.

Data

Datasets

Two complementary benchmarks are used, chosen specifically because CEW lacks subject identifiers (making subject-disjoint splits impossible) while MRL provides them for all 37 subjects.

Training source
CEW (Closed Eyes in the Wild)

10,039 labelled eye images (open / closed) across varied appearance, illumination, and demographics. No subject identifiers, so only image-level partitioning is possible. Used for Protocol P1 (in-domain baseline) and pre-training for P2 and P3. Split: 5,807 train / 4,232 test, resized to 64x64.

Test / generalization target
MRL Eye Dataset

84,898 labelled eye images from 37 distinct subjects, captured under varied lighting (visible and infrared), with and without eyewear. Subject IDs (s0001 to s0037) make strict subject-disjoint partitioning possible. Split: 25 training subjects (53,062 images), 6 validation subjects (7,162 images), 6 held-out test subjects (24,674 images).

Methodology

Three-Protocol Evaluation Framework

Existing drowsiness work mostly uses Protocol P1 by default because CEW has no subject identifiers. P1 numbers look good but tell you nothing about deployment. P2 and P3 reveal what actually happens on unseen subjects and unseen benchmarks.

P1
In-domain baseline (image-level CEW split)

Training and test partitions come from CEW at the image level. Five-frame sequences built within each partition for the CNN-LSTM. This is what most prior work does by default. The numbers here are a calibrated reference point, not a deployment estimate. CNN: 96.50% / CNN-LSTM: 99.95%.

P2
Zero-shot cross-dataset transfer (CEW to MRL)

CEW-trained weights tested directly on the six MRL test subjects with no further training. This quantifies the raw domain-shift gap that real deployment must overcome. CNN drops to 36.73% / CNN-LSTM to 60.64% -- a 59.77 and 39.31 percentage-point collapse from P1.

P3
Subject-disjoint cross-dataset fine-tuning (proposed default)

CEW-trained weights fine-tuned for six epochs on MRL training subjects (lr=1e-4), validated on MRL validation subjects, tested on six held-out subjects the model never saw. No sequence ever crosses a subject or class boundary. This is proposed as the standard reporting protocol going forward. CNN: 94.72% / CNN-LSTM: 93.26% on 24,674 held-out test images.

Models

Reference Architectures

Two architectures that span the dominant design space: a per-frame CNN and a temporal CNN-LSTM. They share a convolutional backbone so the only variable is whether temporal context is added.

Per-frame baseline
CNN

Four 3x3 convolutional blocks (channels 32, 64, 128, 256) with batch normalisation, ReLU, max-pooling, and 2D dropout. Followed by a three-layer fully-connected classifier (512, 128, 2) with dropout 0.5 / 0.25. Lightweight and deployment-friendly. Runs at dashcam frame rates on a Raspberry Pi 4 or Jetson Nano. 2.75M parameters.

Temporal extension
CNN-LSTM

The CNN backbone (without classifier head) applied to five consecutive frames. Per-frame 4096-d features projected to 512-d and processed by a two-layer LSTM (256 hidden, 0.5 inter-layer dropout). The final hidden state feeds a two-layer classifier (128, 2). Designed to distinguish transient blinks from sustained drowsy closure. 4.03M parameters.

The CNN-LSTM misses 1,485 of 8,478 drowsy frames (17.52%) at the default threshold. This asymmetry is what motivates the threshold sweep and Monte-Carlo dropout abstention: dropping the CNN-LSTM threshold from 0.50 to 0.08 pushes drowsy recall from 82.48% to 91.14% at only 2.13% false-alert rate.
